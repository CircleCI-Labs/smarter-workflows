# Smarter Workflows v0.1: spec

Status: building. Decisions: `docs/adr/`. Words: `GLOSSARY.md`.

## Goal

A setup workflow runs the `circleci-smarter` planner. For a branch, the planner prunes the planned workflow of `.circleci/continue.yml` down to the jobs the change can reach. It checks the result against the guardrails and continues the pipeline. On the default branch it runs everything, traces each job's file reads, and rebuilds the impact map.

## Not in v0.1

- History mining and learned rules.
- Model deciders (LLMs or hosted decision models).
- Compose mode.
- Signing the map.
- Multi-workflow pruning (other workflows pass through untouched).
- Matrix expansion (matrix entries always run).
- Expression filters (they are reported and left out of the gate).
- Chunk sidecar integration.

## CLI contract (`circleci-smarter <command>`)

Exit codes for all commands:
- 0: ok;
- 1: fatal error;
- 2: usage error;
- 3: the guardrails failed and the pipeline must not continue.

### `base`

Prints the diff base SHA for the current checkout, or prints nothing (exit 0) when the branch gets a full run.
- Flags: `--default-branch` (default `main`) and `--branch` (default `$CIRCLE_BRANCH`).
- The base is `git merge-base origin/<default> HEAD`. Run `git fetch origin <default>` first when `origin/<default>` is missing.
- On the default branch, on a tag (`$CIRCLE_TAG`), or on any git failure, print nothing.

### `plan`

| Flag | Default | Meaning |
|---|---|---|
| `--config` | `.circleci/continue.yml` | the full continuation config (the catalog) |
| `--workflow` | the only workflow | the workflow to plan; an error if the config has several and none is named |
| `--map` | `/tmp/smarter/impact-map.json` | the impact map; a missing or invalid map means a full run |
| `--base` | computed as `base` does | the diff base |
| `--head` | `HEAD` | |
| `--branch`, `--tag` | `$CIRCLE_BRANCH`, `$CIRCLE_TAG` | |
| `--default-branch` | `main` | |
| `--trigger-type` | empty | `schedule` means a full run |
| `--mode` | `shadow` | `shadow` or `select` |
| `--mandatory` | empty | comma-separated job names |
| `--full-run-paths` | `.circleci/**` | comma-separated globs (doublestar); any match means a full run |
| `--extra-inputs` | empty | declared inputs, `job=glob\|glob,job2=glob` |
| `--ignore-paths` | empty | globs that never select a job (they still count for `--full-run-paths`) |
| `--force-full` | false | |
| `--trace` | `auto` | `auto`, `on` or `off`; `auto` means on for full runs on the default branch |
| `--trace-orb-jobs` | false | also trace orb jobs (assumes their executor is Linux) |
| `--gate-job` | `smarter-gate` | |
| `--gate-image` | a pinned `cimg/base:<yyyy.mm>` | |
| `--map-key-prefix` | `smarter-impact-v1` | the start of the cache key the map job saves the impact map under, `<prefix>-<checksum of the commit>`; letters, digits, `.`, `_` and `-`. Pipelines of one project share its cache, so give each its own, and restore with the same prefix. Restore keys match by prefix: no prefix may start with another one plus a dash |
| `--policy-bundle` | empty | run the pre-flight and repair loop (ADR 6) |
| `--policy-meta` | built from env | JSON passed as `data.meta` |
| `--out` | `/tmp/smarter/continue.yml` | |
| `--report-dir` | `/tmp/smarter/plan` | |

The head commit message forces a full run when it contains `[smarter full]` (case-insensitive) or a `Smarter-Full: true` trailer.

After a usable config is loaded, an internal error never fails the command. The planner writes a full plan instead, records the reason, and exits 0.

### `map build`

```
circleci-smarter map build --traces DIR --revision SHA --out PATH
```

Merges every `*.tsv` in DIR into one map.

### `policy check`

```
circleci-smarter policy check --config PATH --bundle DIR [--meta PATH] [--format text|json]
```

Exit codes: 0 means pass or soft-fail only; 3 means a hard violation.

### `continue`

```
circleci-smarter continue --config PATH [--parameters PATH]
```

- Reads `CIRCLE_CONTINUATION_KEY`, and `CIRCLECI_API_HOST` (default `https://circleci.com`).
- POSTs to `/api/v2/pipeline/continue`.
- Retries on 429 and 5xx: 3 tries, waiting 1, 2 then 4 s.
- **Never prints the key or the request body.** It prints only the status code.

### `version`

Prints the version: `dev-<sha>` when built from source, otherwise the release tag.

## File formats

### Trace TSV

The collector writes one file per job node: `<traces-dir>/<first 16 hex of sha256(job name)>.<node index>.tsv`.

```
# smarter-trace v1
job	<workflow job name, i.e. $CIRCLE_JOB>
node	<$CIRCLE_NODE_INDEX or 0>
method	atime
supported	true|false
reason	<why unsupported, optional>
F	<repo-relative path of a git-tracked file that was read>
D	<repo-relative directory that was listed; "." is the root>
```

### Impact map JSON

```json
{"version":1,"revision":"<sha>","created_at":"<RFC3339>","method":"atime",
 "jobs":{"<job name>":{"files":["a/b.go"],"dirs":["a"],"complete":true,"nodes":2}}}
```

- Files and dirs are the union over nodes, sorted.
- `complete` is true only if every node was supported.

### Plan report

`plan.json`:

```json
{"version":1,"mode":"select","full":false,"full_reason":"","workflow":"ci",
 "base":"<sha>","head":"<sha>","branch":"x","map_revision":"<sha>","map_created_at":"...",
 "changed":[{"path":"a/b.go","status":"M"}],
 "jobs":[{"name":"api-test","run":true,"reasons":["reads services/api/main.go"]}],
 "gate":{"name":"smarter-gate","requires":["..."]},
 "guardrails":{"status":"PASS","repairs":[],"violations":[]},
 "warnings":[]}
```

`plan.md` is a human summary for the job's artifacts and (later) a PR comment:
- one line: the mode, N of M jobs running, and the full-run reason if there is one;
- a table of jobs, with run or skip and the first reason;
- up to 50 changed files.

## The algorithm (planned workflow W)

1. **Full run.** Plan a full run when any of these holds:
   - `--force-full`;
   - the branch is the default branch, or there is a tag;
   - the trigger type is `schedule`;
   - the head commit asks for one;
   - there is no base, or no usable map;
   - a changed path (old or new) matches `--full-run-paths`;
   - W has a `when` or `unless` that is not a literal boolean.
2. **Changes.** Run `git diff --name-status -M -z <base> <head>`.
   - Renames count as the old path deleted plus the new path added.
   - Paths that match `--ignore-paths` are dropped before step 3.
3. **Direct selection.** For each entry J of W (its effective name is `name:` if set, else the job reference):
   - **approval** entries are decided by the closure in step 4;
   - a **matrix** entry runs;
   - a **mandatory** job runs;
   - a job whose **extra inputs** match a changed path runs;
   - a job with **no map entry, or an incomplete one**, runs;
   - a job that **read a changed file** runs;
   - for an **added or deleted path P**, J runs if J listed the parent directory of P. It also runs if J listed any ancestor directory whose direct child on P's path is a directory that is new at the head or gone from the base (use `git ls-tree` at the base and the head);
   - **otherwise J is skipped**, with the reason "inputs unchanged".
4. **Closure.**
   - Every `requires` ancestor of a selected job is selected, approvals included.
   - Producers are local jobs with `persist_to_workspace`; consumers are local jobs with `attach_workspace`. Orb jobs count as both.
   - When a selected producer K has a consumer J downstream of it, J is selected.
   - Repeat both rules until nothing changes.
5. **Will it run?** Evaluate `filters` for the current branch or tag:
   - CircleCI semantics: string or list, and `/regex/` is a full match;
   - jobs don't run on tags without a matching `tags.only`;
   - expression (string) filters are unknown; they are reported.
6. **Gate.** Add the job `smarter-gate`:
   - its definition: docker `--gate-image`, `resource_class: small`, and one `run` step;
   - its workflow entry requires every selected job that will run, except jobs downstream of an approval and jobs with unknown filters;
   - if nothing else is selected, W contains only the gate.
7. **Emit.**
   - **Select mode:** remove the skipped entries from W. Drop any `requires` names that are no longer present; there should be none, because of the closure.
   - **Shadow mode:** keep every entry. The report still shows what select mode would have skipped.
   - Every other part of the config is untouched: other workflows, jobs, orbs, comments and key order.
   - Never add pipeline parameters. Emit literals only.
8. **Trace** (full runs on the default branch, when `--trace` resolves to on):
   1. On every non-approval entry of W that is a local Linux job (docker, or machine with a Linux image), append `post-steps`. Orb jobs are included only with `--trace-orb-jobs`.
      - a `run` step named `smarter: collect trace`, with `when: always`, `shell: /bin/sh`, and as its command the embedded `collect-trace.sh`;
      - `persist_to_workspace` with root `/tmp/smarter` and paths `[traces]`.
   2. If the spike (W3) shows that `checkout` itself reads files, also insert a step right after `checkout` in those local job definitions that resets the atime of tracked files to epoch 0.
   3. Add the job `smarter-impact-map`. It requires every traced entry that is not downstream of an approval. Its steps:
      1. write `.smarter-version` (the planner's own version, as a literal);
      2. `restore_cache` with key `smarter-bin-v1-{{ checksum ".smarter-version" }}-{{ arch }}`;
      3. `attach_workspace` at `/tmp/smarter`;
      4. `map build`;
      5. write `.smarter-key` (`$CIRCLE_SHA1`);
      6. `save_cache` with key `<--map-key-prefix>-{{ checksum ".smarter-key" }}` (by default `smarter-impact-v1-{{ checksum ".smarter-key" }}`) for `/tmp/smarter/impact-map.json`;
      7. `store_artifacts`.
9. **Guardrails** (when `--policy-bundle` is set):
   1. `policy.Check` the emitted config.
   2. For a hard violation carrying `[smarter:require-job=NAME]`, force NAME and plan again (at most 3 rounds).
   3. If hard violations are left, plan a full run and check again.
   4. If that still fails, exit 3.
   5. Soft violations go into the report as warnings.

## Guardrail bundle (`policies/`)

- `package org`, using CircleCI's policy conventions (`policy_name`, `enable_hard`) and `data.circleci.config` helpers where they fit.
- The settings are constants at the top of the file, for projects to edit.
- Rules:
  1. **Required jobs** (`security-scan` by default) are present in every workflow of a non-setup config. The message carries the repair code.
  2. **Restricted contexts** (e.g. `deploy`): allowed only on listed jobs, only on listed branches or on tags, and only downstream of an approval job.
  3. **Resource classes** come from an allowlist. Check the source jobs, and `_compiled_` when it is present.
  4. **Registry orbs** are pinned to an exact `x.y.z`.
  5. **URL orbs** carry a 40-hex commit SHA.
  6. A continuation config does **not declare `setup: true`**.
- Tests: Rego `_test.rego` files plus Go fixture tests through `internal/policy`. Locally there is no `_compiled_`, so rules must cope with it being absent.

## The orb and the dogfood pipeline

- **`orb/orb.yml`** (single file):
  - command `install` (`source: release|build`; `build` runs `go build` from the current checkout and saves the `smarter-bin-v1-…` cache);
  - command `collect-trace`;
  - job `plan`, with parameters mirroring the `plan` flags. It runs: checkout, install, `base` → `.smarter-key`, restore the map cache (exact key, then the `<map-key-prefix>-` prefix, `smarter-impact-v1-` by default), `plan`, store the report, `continue`.
- **`.circleci/config.yml`**: setup, with an inline `plan` job that builds from source (the orb isn't published yet).
- **`.circleci/continue.yml`**: this repo's own full pipeline, which includes:
  - Go tests and lint;
  - policy tests;
  - shellcheck and collector tests;
  - orb validation;
  - `security-scan` (mandatory; `govulncheck`);
  - a build → e2e pair over a workspace;
  - a tag-only release after a `hold-release` approval.

## Tests and gates (before any merge to main)

- `gofmt -l` is empty, and `go vet ./...` and `go test ./...` pass.
- Golden tests for the planner scenarios in `examples/monorepo/`:
  - docs-only;
  - one service;
  - a shared library;
  - an added file in a listed directory;
  - a `.circleci` change;
  - no map;
  - a mandatory job missing and then repaired.
- Every config the planner generates validates with `circleci config validate` when the CLI is present. Set `REQUIRE_CIRCLECI_CLI=1` in CI so that a missing CLI fails, not skips.
- Collector tests run in a temp git repo. With `REQUIRE_ATIME=1`, a filesystem without atime support fails the test.
- The continuation client is tested against `httptest`, and the test asserts the key never appears in the output.
